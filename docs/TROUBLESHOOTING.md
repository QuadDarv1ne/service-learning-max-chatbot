## Бот не работает

### Симптом: Бот не отвечает на сообщения в MAX

#### Шаг 1. Проверить здоровье системы

Откройте в браузере или curl:
```bash
curl https://your-domain.ru/api/health
```

Должен вернуть `"ok": true` и все чеки `database.ok: true`, `botTokenConfigured: true`, `webhookSubscribed: true`.

Если `ok: false` — см. конкретные проблемы ниже.

#### Шаг 2. Проверить подписку webhook

В админ-панели:
- Раздел "Настройки" → карточка "Здоровье системы"
- Статус "Webhook подписка" должен быть 🟢 "Активна"

Если 🔴 "Не подписан":
1. Проверьте, что "Токен бота" указан и "Проверить бота" возвращает имя
2. Проверьте, что "URL вебхука" корректен (HTTPS, заканчивается на `/api/max/webhook`)
3. Нажмите "Подписать webhook"
4. Если ошибка — посмотрите сообщение, обычно понятно (401 = невалидный токен, etc.)

#### Шаг 3. Проверить логи

- Раздел "Логи обращений"
- Фильтр: `direction=in` за последние 30 минут
- Если есть записи — ваши сообщения доходят до приложения, проблема в отправке ответа
- Если записей нет — webhook не работает

#### Шаг 4. Проверить ошибки MAX API

- Раздел "Логи обращений"
- Фильтр: `direction=out`, посмотреть колонку "MAX API"
- Если есть красные бейджи HTTP-кодов — см. [Проблемы с MAX Bot API](#проблемы-с-max-bot-api)

### Симптом: Бот отвечает, но не на все сообщения

#### Проверить логику бота

1. Раздел "Логи обращений"
2. Найти сообщение, на которое бот не ответил
3. Посмотреть в `source` колонку:
   - `search` — бот нашёл ответы в FAQ и показал кнопки
   - `llm` — бот ответил через ИИ (если в базе нет точного совпадения)
   - `fallback` — нет ответа в базе, ИИ выключен или не справился
   - `off_topic` — запрос не связан с программой

Если `fallback` или `off_topic` — нужно пополнять базу знаний или корректировать off-topic фильтр.

### Симптом: Бот отвечает долго (>5 секунд)

#### Причины

1. **LLM-фолбэк** — ИИ генерирует ответ, обычно 1-3 секунды. Нормально.
2. **Сетевые проблемы** — MAX API медленно отвечает
3. **Перегрузка сервера** — мало ОЗУ

#### Что делать

- Раздел "Аналитика" → "Время ответа" — посмотрите avg/p95
- Если p95 > 5000 мс — сообщите администратору
- Если всего несколько запросов медленные — это нормально (LLM)

### Симптом: Бот отвечает не по теме

#### Проверить off-topic фильтр

Если пользователь спрашивает "какая погода в Москве?" и бот пытается ответить через ИИ вместо отказа — фильтр работает слишком лояльно.

Решение: попросить администратора скорректировать STRONG/WEAK термины в `src/lib/llm.ts`.

#### Проверить релевантность ответов

Если бот на запрос "как зарегистрироваться" показывает ответ "Сколько длится программа?":
- Откройте раздел "База знаний"
- Найдите вопрос про регистрацию
- Добавьте больше **ключевых слов** с синонимами
- Уберите общие слова из `keywords`, которые встречаются в других ответах

## Админ-панель не работает

### Симптом: Не могу войти в админ-панель

#### Шаг 1. Проверить пароль

- Пароль хранится в `.env` в переменной `ADMIN_PASSWORD`
- По умолчанию `admin123` — смените в продакшене!

Если забыли:
1. Отредактируйте `.env`:
   ```bash
   nano /opt/max-bot/.env
   # Изменить ADMIN_PASSWORD=your-new-password
   ```
2. Перезапустите сервис:
   ```bash
   sudo systemctl restart max-bot
   ```

#### Шаг 2. Очистить cookie

Если пароль правильный, но пишет "Неверные учетные данные":
1. Откройте DevTools браузера (F12)
2. Вкладка Application → Cookies → ваш-домен
3. Удалите cookie `max_bot_admin_session`
4. Обновите страницу
5. Войдите снова

#### Шаг 3. Проверить неудачные входы

- Раздел "Журнал действий" → фильтр `action=login_failed`
- Если много попыток с одного IP — возможно атака перебором
- Смените пароль + (опционально) заблокируйте IP в Caddy/Nginx

### Симптом: Страница белая/не загружается

#### Шаг 1. Проверить сетевое соединение

- Откройте URL в браузере — должно показать страницу входа
- Если ERR_CONNECTION_REFUSED — приложение не запущено

#### Шаг 2. Перезапустить сервис

```bash
sudo systemctl status max-bot
sudo systemctl restart max-bot
sudo systemctl status max-bot
```

Должен показать `active (running)`.

#### Шаг 3. Посмотреть логи приложения

```bash
sudo journalctl -u max-bot -n 50 --no-pager
```

Или:
```bash
tail -100 /opt/max-bot/dev.log
```

Ищите ошибки с `error`, `Error`, `EADDRINUSE`, `ENOMEM`.

### Симптом: "Internal Server Error" (500)

#### Причина: Скорее всего, проблема с БД

1. Проверить файл базы:
   ```bash
   ls -la /opt/max-bot/data/custom.db
   ```
   Если файла нет — выполнить `bun run db:push` от пользователя maxbot.

2. Проверить права:
   ```bash
   sudo chown maxbot:maxbot /opt/max-bot/data/custom.db
   sudo chmod 600 /opt/max-bot/data/custom.db
   ```

3. Проверить что БД не повреждена:
   ```bash
   sqlite3 /opt/max-bot/data/custom.db "PRAGMA integrity_check;"
   ```
   Если ошибка — восстановить из бэкапа.

## Проблемы с MAX Bot API

### Симптом: HTTP 401 Unauthorized

**Причина:** Невалидный токен бота.

**Решение:**
1. Зайти на **Портал для бизнеса MAX** — [business.max.ru/self](https://business.max.ru/self) → раздел **"Чат-боты"** → карточка бота → **⋮** → **Настройки** → поле **"Токен доступа"**
2. Скопировать токен либо обновить его (**значок обновления**), если есть подозрение на утечку
3. В админ-панели → "Настройки" → вставить новый токен → "Сохранить"
4. Нажать "Проверить бота" — должно вернуть имя и ID

> Подробнее о получении и обновлении токена — в [Руководстве администратора](./ADMIN_GUIDE.md#токен-бота-max).

### Симптом: HTTP 429 Too Many Requests

**Причина:** Превышен лимит 30 запросов в секунду к MAX Bot API.

**Решение:**
- Это нормально при массовых рассылках (но бот не делает рассылок)
- Если лимит превышен при обычной работе — обратитесь в техподдержку MAX
- Временное решение — добавить задержку между запросами в `lib/max-api.ts`

### Симптом: HTTP 503 Service Unavailable

**Причина:** MAX Bot API временно недоступен.

**Решение:**
- Подождать 5-10 минут
- Проверить статус MAX на [max.ru](https://max.ru) или в Telegram-канале MAX
- Бот автоматически повторит при следующем сообщении пользователя

### Симптом: Webhook не подписывается

#### Проверить URL

- URL должен быть **HTTPS** (MAX не принимает HTTP с мая 2025)
- URL должен заканчиваться на `/api/max/webhook`
- URL должен быть общедоступным (не localhost)

Для тестирования локально:
```bash
# Установить ngrok
ngrok http 3000
# Получите URL вида https://abc123.ngrok.io
# Вставьте в настройки: https://abc123.ngrok.io/api/max/webhook
```

#### Проверить сертификат

- Должен быть от доверенного CA (Let's Encrypt, DigiCert, etc.)
- Самоподписанные не работают
- Сертификаты Минцифры РФ — работают

Проверить:
```bash
curl -v https://your-domain.ru/api/max/webhook
# Должен показать действительный SSL-сертификат
```

#### Проверить firewall

Убедитесь, что порт 443 открыт:
```bash
sudo ufw status
# Если порт 443 не открыт:
sudo ufw allow 443/tcp
```

## Проблемы с базой знаний

### Симптом: Добавил ответ, но бот его не находит

#### Проверка 1. Опубликовано

- Раздел "База знаний"
- В строке ответа — переключатель "Опубликовано" должен быть зелёным

#### Проверка 2. Категория опубликована

- Раздел "Категории"
- Категория, к которой относится ответ, должна быть опубликована

#### Проверка 3. Ключевые слова

- Откройте ответ на редактирование
- Поле "Ключевые слова" — должно содержать синонимы запроса пользователя
- Если пусто или мало — добавьте (минимум 5-10 слов)

#### Проверка 4. Длина слов

Поиск игнорирует слова короче 3 символов и стоп-слова.

Если ваш запрос "как войти" — бот ищет только по слову "войти" (1 слово). Если в FAQ это слово есть в `keywords` — найдёт. Если нет — нет.

Решение: добавить больше вариантов ключевых слов.

#### Проверка 5. Тест в боте

1. Откройте бота в MAX
2. Отправьте свой вопрос текстом
3. Бот должен показать кнопки с релевантными ответами
4. Если не находит — попробуйте переформулировать вопрос

### Симптом: Все ответы пропали

#### Возможные причины

1. Кто-то выполнил `bun run scripts/seed.ts` — он **перезаписывает** базу знаний
2. Импортировали старый JSON-бэкап (стирает текущую базу)
3. Случайно удалили все категории

#### Решение: Восстановить из бэкапа

1. Раздел "Настройки" → "Бэкап и расширенные действия" → "Импорт базы знаний"
2. Выберите последний JSON-бэкап
3. Подтвердите восстановление

Или через SQLite бэкап (если есть):
```bash
sudo systemctl stop max-bot
cp /backup/custom-20260924.db /opt/max-bot/data/custom.db
sudo chown maxbot:maxbot /opt/max-bot/data/custom.db
sudo systemctl start max-bot
```

### Симптом: Импорт базы знаний зависает

#### Причина: Слишком большой файл

JSON-бэкап до 5 MB обычно импортируется <5 секунд. Если больше — проверьте:
- Файл валидный JSON (`cat file.json | python3 -m json.tool`)
- Содержит `categories` с массивом

Решение для больших баз:
- Разбить на несколько JSON-файлов и импортировать по частям
- Или напрямую через SQLite:
  ```bash
  sqlite3 /opt/max-bot/data/custom.db < your-data.sql
  ```

## Проблемы с аналитикой и логами

### Симптом: Аналитика показывает 0 активности

#### Проверка

- Раздел "Аналитика" → проверьте период (попробуйте "Всё время")
- Раздел "Логи обращений" за период — есть ли записи
- Раздел "Настройки" → "Здоровье системы" → "Сообщений 24ч"

Если везде 0 — у бота не было обращений (проверьте webhook подписку).

### Симптом: Время ответа 0 мс или очень большое

- 0 мс — нет данных (нет сообщений за период)
- Очень большое (>30 секунд) — вероятно, таймаут запроса

Причина: ИИ долго генерирует ответ или сетевые проблемы.

### Симптом: Экспорт CSV пустой

#### Проверка

1. Раздел "Логи обращений" — посмотрите, есть ли данные за период
2. Фильтры — снимите все фильтры, попробуйте без них
3. Если используете `dateFrom/dateTo` — проверьте формат (должен быть ISO `YYYY-MM-DD`)

### Симптом: Журнал действий пустой

Если только установили — журнал пустой, пока никто не входил в админку.

Если было много действий, но они не отображаются:
- Фильтр по `ok=true` или `ok=false` — проверьте
- Дата — проверьте диапазон (возможно все действия были раньше)

## Проблемы с разворачиванием

### Симптом: `bun install` не работает

#### Причина 1: Нет bun

Установите:
```bash
curl -fsSL https://bun.sh/install | bash
```

#### Причина 2: Старая версия bun

Обновите:
```bash
bun upgrade
```

#### Причина 3: Проблемы с сетью / npm registry

Используйте yarn или npm:
```bash
yarn install
# или
npm install
```

### Симптом: `bun run db:push` падает с ошибкой

#### Причина 1: Файл БД заблокирован

Если запущен процесс — остановите:
```bash
sudo systemctl stop max-bot
# или
pkill -f "next dev"
pkill -f "next-server"
```

#### Причина 2: Нет прав на запись в директорию

```bash
sudo chown -R $USER:$USER /opt/max-bot
chmod -R u+w /opt/max-bot/data
```

#### Причина 3: Повреждённая БД

```bash
# Проверить
sqlite3 db/custom.db "PRAGMA integrity_check;"
# Если ошибка — удалить и пересоздать
rm db/custom.db
bun run db:push
bun run scripts/seed.ts
```

⚠️ Это потеряет все данные. Используйте только если нет бэкапа или бэкап точно повреждён.

### Симптом: Next.js не запускается (порт занят)

#### Причина: Порт 3000 уже используется

```bash
# Найти процесс
lsof -i :3000
# или
sudo netstat -tnlp | grep 3000

# Завершить
kill PID
# или
sudo kill -9 PID
```

#### Решение: Использовать другой порт

Измените в `package.json`:
```json
"dev": "next dev -p 3001 2>&1 | tee dev.log"
```

Или через env:
```bash
PORT=3001 bun run dev
```

⚠️ Если меняете порт — обновите URL webhook в настройках.

### Симптом: Ошибка "module not found"

После обновления зависимостей:
```bash
rm -rf node_modules
rm bun.lock  # или package-lock.json
bun install
bun run db:generate  # перегенерировать Prisma клиент
bun run dev
```

## Чек-лист первичной диагностики

При любой проблеме — проверьте по порядку:

- [ ] Сервис запущен? `sudo systemctl status max-bot`
- [ ] health endpoint работает? `curl https://your-domain/api/health`
- [ ] БД отвечает? В админке "Дашборд" должен показывать цифры
- [ ] Токен бота валиден? "Настройки" → "Проверить бота"
- [ ] Webhook подписан? "Настройки" → статус "Активна"
- [ ] Последние логи есть? "Логи обращений" → за последний час
- [ ] Журнал действий есть? "Журнал действий" → последние действия
- [ ] Диск не переполнен? `df -h`
- [ ] ОЗУ достаточно? `free -m` (available > 200)
- [ ] Сеть доступна? `ping platform-api2.max.ru`

Если все чеки ✅ — проблема специфичная, см. соответствующий раздел выше.
